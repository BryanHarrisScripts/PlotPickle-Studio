# PlotPickle Studio — fal Player and Shot Batch (v0.8.40)

This is the integrated *in-chat* player and production bridge for REEL and ONCE. Route **HOME → Storyboard → REEL → verified story → Produce → Watch fal Clips** here. It does not install a duplicate player, copy a fal HTML widget into the plugin bundle, create a separate hosted sidebar, or require a Windows app for viewing and generating provider media. Render the connected fal plugin's actual native media viewer using `mcp__fal__show_media` for one completed job or `mcp__fal__show_media_batch` for several jobs (preferred for 2–8). It displays the user's completed provider videos with source context and separately provides original MP4 links. Never construct UI previews out of unverified media or promise that a source has been copied into the ChatGPT file sandbox.

## Editorial order and safe batch assembly

A regular shot is 3 seconds × 24 fps = **72 frames**. Three consecutive shots occupy frames 0–71, 72–143, 144–215, or 00:00–00:09. Original fal source footage may be at 30 fps / 90 frames per three-second clip; retain those originals and conform copies separately. The source PPF still determines the screenplay and position identity. Source media for this one sequence is never bundled in plugin code or public GitHub.

For hosts that have actual local MP4 bytes, use the read-only `scripts/assemble-shot-batch.py` with a private v1 batch manifest (see `references/batch-handoff-contract.md`):

`python3 scripts/assemble-shot-batch.py --project /private/story.ppf.json --manifest /private/shot-batch.json --video-root /private/fal-originals --out /private/verified-three-shot-draft`

It refuses stale source ID/revision/SHA, nonconsecutive shots, unverifiable source passage mapping, unsafe media paths and URLs, media byte mismatches, short or undecodable MP4s, mixed dimensions, output overwrite and unverified final frame counts. Once real originals are present it decodes them, creates 72-frame/24fps individual silent H.264 conform files, assembles one 24fps silent MP4, full-decodes and hashes every result, and writes `draft-receipt.json`. It does **not** request fal credits or access the network. It never mutates the PPF, marks native Save/Lock, or asserts that an authenticated editor or Windows host has been reached.

For the Three-Shot reference, a conform receipt is a `verified-draft-sidecar`, not `native-imported-draft` or creative approval. The Windows v0.8.31 editor cannot yet render multi-shot timelines, so keep its status *not-connected / multi-shot import pending* unless later validated. Individual verified clips may be reviewed and registered via separately supported editor intake. Export the combined MP4 as an editable source-linked draft, not an approved picture lock. Do not tell users they must install Windows merely to watch fal's native player.

Run `python3 scripts/test-assemble-shot-batch.py` for offline synthetic coverage. A passing test does not establish live fal-to-ChatGPT byte transport or editor acceptance.
