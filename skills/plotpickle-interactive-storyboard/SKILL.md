# Interactive PlotPickle storyboard (v2.0.32)

The creator accepted the in-chat expandable storyboard card: **one PlotPickle connection, one Elara, one ChatGPT conversation**. Preserve local carousel swipe and Previous/Next controls, 5 page selectors, 25 position index, Expand/Collapse and six inspector tabs (Script, BEAT, Visual, Continuity, Production, Status). The hosted visual editor remains an optional fallback until tool-backed parity is independently verified. Do not automatically open an embedded panel or website.

## Source-backed inspector (new in v2.0.32)

Read `references/source-backed-inspector-v1.md` and use the bundled **read-only** `scripts/inspect_saved_storyboard.py` after accessing an authorized current PPF from Library/conversation and verifying the exact raw source SHA-256 and revision against `studio_list_projects` / `studio_check_project`. The script produces 25 labeled shots with true source-linked planning descriptions, camera plans, passage IDs and distinct PPF Save/Lock and visual approval states. Tests: `python3 scripts/test_inspect_saved_storyboard.py` use only fictional fixtures. Do not bundle a creator's actual PPF or media in this plugin.

For inactive saved projects, this PPF-based source snapshot can populate an in-chat read-only inspector **without switching the active Studio project**. Always check `studio_get_state`; a saved catalogue entry does not imply an active project. The HTML/contact sheet from Library is a reference montage, not 25 original verified image files. Show actual per-shot images only after independently obtaining authentic WebP bytes from Studio (active project) or authorized Library media. Never substitute internet images for source art.

Important example: PPF `savedMarkerPresent=true`, `locked=true` and `visualApproval.state='pending-user-review'` must be displayed as distinct source facts, not collapsed into “approved.” Shot 01 may have explicitly approved art while another 24 remain pending explicit visual review despite default locks. Distinguish Studio lock (creator human approval of that exact version) from pre-existing native PPF default locks. Source `authoredBeats=[]` does not prove that separately saved Studio BEATs are absent.

## Review handoff and actual changes

`Review with Elara` submits a normal new ChatGPT turn with exact film, block, mini-block, shot, source revision/hash, and **read-only** intent. Reconfirm source and active Studio state on that turn. Never auto-open, save, unlock, generate, pay or mutate from navigation.

For explicit **load film**, use fresh `studio_get_state`, `studio_check_project`, then guarded `studio_open_project` only if creator has selected that project. For authorized **Save / Approve & Lock / Unlock / Edit / Undo / Resubmit**, first verify active identity, current Studio expected revision and exact media hash; call `studio_apply_action` with allowed parameters; independently read `studio_get_state` again before reporting success. These Studio sidecar writes do not update native PPF. Paid regeneration requires actual provider pricing and job-specific approval. Avoid disabled-but-misleading “working” controls in a read-only card.

Source-backed read-only status is a separate acceptance gate from a functioning live per-shot WebP viewer, persisted Studio review actions, exact media playback, six-track editor parity, native PPF writeback and ChatGPT host-side fullscreen. Do not claim those gates complete on the strength of this skill update. Preserve the creator's projects, private data, account binding, locks, cuts and provider credentials unchanged.

Retain layout and device details in `references/interaction-contract-v2.md`. The ChatGPT app controls outer host window/panel placement: never promise a system-native slide-out panel from a skill update.


## v2.0.33 — live MCP-backed in-chat review (November 13, 2026)

The creator requested go-live of the working in-chat swipe/expand inspector design. Prefer **real saved source imagery** and **live Studio state** rather than placeholders when the specific authenticated project is loaded. This supplements the v2.0.32 source-backed inspector; preserve all older review, approval, media, lesson and production capabilities.

1. **Load explicitly, never silently:** call `studio_list_projects` and `studio_get_state`; for a user-authorized project opening, call `studio_check_project` and then `studio_open_project` with the current `expectedRevision` and exact `validationFingerprint`. Re-read state and verify project ID, source revision and raw SHA. Do not automatically select a project merely because the user opens HOME. An already loaded matching project is no-op.
2. **Real media:** for each actual registered shot use `studio_get_image({shot})` to verify the saved WebP bytes/hash when supported. In a ChatGPT conversation, user-authorized Library files can be materialized via chat-side Files tools and SHA-256-checked against the current PPF. If native chat widgets cannot consume the tool's `dataUrl`, derive small temporary review images in the current conversation runtime from verified original media; do **not** publish private artwork or PPFs in the plugin release. Display the actual file where supported, not AI-invented or online lookalikes. UI swipe/page/shot selection stays client-local.
3. **Actual BEATs:** `studio_get_state` includes `shots[].beat` when saved; separately reopen a selected record using `studio_get_beat({shot})` and check `status=saved` / `readbackVerified` before describing it as durable. A source PPF with `authoredBeats: []` can still have a separately saved, screenplay-derived Studio BEAT; do not confuse these states.
4. **Approval is multi-layered:** show `ppfSaved`, `ppfLocked`, source approval evidence, `reviews['image:N']` Studio sidecar status, and actual image hash separately. Current policy: exact-source locks count as creator approval under the approved lock-includes-human-approval model, even if source only records one *explicit user-message* approval; do not label the other source-locked shots unapproved, and do not invent 25 explicit approval messages. Existing Studio review locks are distinct and should not be overwritten.
5. **Real actions only:** for Save, Approve & Lock, Unlock, Resubmit, request-image, cue edit and Undo, the button MUST issue a normal new user turn naming the selected shot and intended operation. Elara rereads current Studio state and exact project/source and asset SHA, then calls `studio_apply_action` only if the user actually authorized that action and all revision/hash arguments match. Reopen state before reporting saved. Already locked shots show their existing lock, not a fake save button; avoid duplicate operations. Native Library PPF writeback remains unavailable. No direct host/tool invocation from client-local carousel transitions.
6. **Regeneration safety:** a Request regeneration button opens an image-revision discussion, not a paid job. The locked original is unchanged; provider cost/model/settings must be reviewed and explicit job-specific approval obtained before spending, with a new unapproved comparison candidate after generation.
7. **Render is a draft:** use `studio_prepare_render` to verify six-track fingerprint, fps/frames, timeline revision and attached render; optionally `studio_get_render` for real hash-checked playback. A current attached draft isn't an approved master, nor does it prove all audio lanes have sources. Video source vs storyboard still lineage differences remain visibly flagged where present.
8. **Go-live definition:** skill/plugin routing updated; source media and MCP state read back; in-chat interactive card functioning in creator chat. These do NOT claim a changed Sites-hosted HTML application, an automatic Library picker, native PPF writeback, third-party account acceptance or user device gestures unless independently tested. Keep existing Sites service and visual editor fallback, with no second connection, install or login.

See `references/live-chat-review-contract-v1.md` for source checks, UI details and acceptance boundaries. This plugin update never packages user storyboard files and never modifies a saved film by itself.
