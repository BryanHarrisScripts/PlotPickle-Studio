## Non-negotiable Skin V1 rules

1. On all five approved screen types, maintain `PLOTPICKLE / STUDIO` at upper left, the current surface label at upper right, one breadcrumb row including Back, and a consistent matte black/off-white restrained-purple design; compact border, 4px spacing rhythm, natural wrapping and exact ordering from `skin-v1.json`.
2. HOME always shows exactly **Meet Elara, Learn, Storyboard, Connected Services** as four primary cards, in this order, then a quiet Continue Creating item *only if* the user's actual saved project was reopened and verified. Never turn REEL or ONCE into a fifth HOME choice.
3. STORYBOARD always shows two equally weighted **REEL** and **ONCE** options above **Your Stories** and a quiet **Create a story** entry. REEL labels Characters/Worlds/Scenes/Visuals/Produce; ONCE labels People/Places/Memories/Illustrations/Preserve. One shared PPF engine. Never invent a story list or falsely identify a Library folder as a ChatGPT Project.
4. STORY MAP always uses **I II III IV** selector in one line, three Sequence groups for selected Act, two Block cards per group (global Blocks 01–24), plus selected Block summary with four Mini entries. Use titles and statuses from exact current authorized PPF, never hard-coded The Third Bell examples. Underlying structural numbers are a scaffold, not proof of 2,400 generated shots.
5. MINI-BLOCK always uses four Mini selectors, compact evidence summary, a **5×5** grid of exactly 25 shot positions, legend, and selected-shot inspector with Script/Beat/Prompt/Image/Continuity/Save-Lock tabs, in that order. Empty planning slots are not authored shots. Image status never implies approval.
6. IMAGE REVIEW always shows the exact selected image if bytes are accessible, separate candidate variations and provenance, four independent statuses (Human Approved / PPF Saved / PPF Locked / Media Verified), and the Script/Prompt/Continuity/Audit tabs. If no image can be read, render a clearly labelled placeholder, not a generic Internet image or fabricated success state.
7. Save/Lock interaction *design* is approved, but real Save/Lock/Unlock/Regenerate actions require exact latest PPF/file version, verified media, guarded writes and independent readback using existing `read-plotpickle-project` workflows; do not change PPF or signal success by UI state alone. No writer, permissions, default batch actions or provider spending became authorized by publishing Skin V1. See `save-lock-transaction.v1.json`.
8. Production Handoff, Connected Services, Editor, Character/World builders, ONCE memory capture and other UI surfaces are **not** visually approved in Skin V1; preserve their existing routing and functionality without pretending these are locked designs. The pending Production Handoff Candidate 01 is excluded from this published skin.
9. The plugin has no permanent hosted MCP sidebar or custom native UI renderer. Apply the canonical layout consistently in supported in-chat cards and host controls. In a host without interactive layouts, preserve the exact text order and offer conversational navigation. Buttons may select local preview state; a modifying button must trigger a real tool-backed turn or be unavailable. No claim of pixel-identical rendering on every device.
10. Keep personal project IDs, titles, snapshots, PPF files, media and image hashes in authorized ChatGPT Projects/Library, never bundled in the plugin. Pin actual source ID/revision/hash, respect prior approvals and candidate distinctions. Never use design mockup states as current story facts.
