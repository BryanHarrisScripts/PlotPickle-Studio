# PlotPickle Creative Editor — prototype contract v1

Authority: the `.ppf.json` screenplay, shot-address mappings and image Save/Lock remain source-owned and are never mutated by the editor. `editor-draft.json` is a separate, noncanonical sidecar at `fps=24` and revisions increment on every accepted edit. Video generation receipts, local clip hashes, creative approval and PPF acceptance are independent facts.

Coordinates: (act, sequence, block, miniBlock, shot) refer to canonical 4 Acts / 12 Sequences / 24 Blocks / 96 Mini-Blocks / up to 25 storyboard positions each. Each normal position is 72 frames at 24 fps; footage may arrive at 30 fps and must be conformed after independently retrieving/decoding the original. No resubmission to fal or billing is involved in conversion.

Timeline tracks: video, dialogue, action, Foley, ambience, music. All clips have stable IDs, `startFrame`, `durationFrames`, optional `mediaId` and `sourceShot`, `gainDb` and notes. Every mutation supplies `expectedRevision`; stale revisions fail. Undo creates another revision with a restored prior snapshot rather than rewriting history. This release provides editable cue *markers* on non-video tracks, not speech synthesis, lip-sync or audio mixing. Do not label its audio export final mix.

Local bridge: Windows receiver binds strictly to loopback `127.0.0.1`, accepts only exact HTTPS fal media-file paths on `v3b.fal.media` with no redirects or credentials, checks public DNS endpoints, caps download size, probes, fully decodes and converts media with FFmpeg, verifies 24 fps and exact frame count with a second decode and SHA-256, then stores verified clips under the selected local `Videos/PlotPickle/` project folder. No arbitrary shell command or remote path is accepted. It has no HTTP listener on the public network, and should never be directly exposed by port forwarding.

ChatGPT transport: the Plugin Creator release includes the portable editor/receiver code and discovery prompts. It does not automatically install the Windows code, attach a new MCP server, or permit ChatGPT tools to invoke `127.0.0.1` across sandbox boundaries. A later authenticated outbound agent/MCP connection must expose bounded actions such as `editor.status`, `editor.ingestApproved`, `editor.getTimeline`, `editor.applyPatch` and `editor.exportDraft`. Require scoped authorization, session identity, path allowlist, provenance, replay keys and readback before giving such actions a "Connected" state. No secret may be stored in a PPF.

Acceptance gates: a source-backed edit is distinct from a playback preview; a fal receipt is distinct from bytes; bytes are distinct from decoded verification; 24-fps conformance is distinct from original provider output; editor draft is distinct from native PPF Save/Lock. Report the exact last confirmed gate. Offline unit tests prove only local code paths, not Windows installation, live fal CDN delivery, ChatGPT embedded host interactivity or native PPF write integration.


Audio v0.8.31 addendum: The editor draft independently registers verified 48k local WAV `audioAssets`, referenced by audio clip `audioId`, exact frame timing, gainDb and muted state; raw paths remain server-private. The initial ocean/gulls are procedurally synthesized temporary demos, not final Foley or field recordings. Validate WAV payload bytes/codec/duration and local Origin before storing them; hash-check sources at each render. The on-demand renderer uses FFmpeg to build 48k stereo audio, with 2000 audio samples per 24-fps frame, mixes unmuted/bound sources and discloses missing cues. A picture+sound render is a verified local DRAFT, not PPF acceptance. Prior renders, revisions and native Save/Lock are not overwritten. This does not establish a live ChatGPT→Windows transport; no general-purpose MCP agent has been installed by the plugin update.
