# Scope and evidence limits

The reader and authoring scripts make no network or model calls and require no
publisher-hosted service. Native image generation is a separate host operation,
only when requested and available. No publisher account, secret or fixed user file
ID is bundled. Installation does not provide execution, file storage, image tools,
background workers, or establish billing terms.

Read-only inspection remains unchanged. Writer commands create explicit local
snapshots for authorized import/development/registration operations. Every existing
project operation pins project ID, revision and SHA-256; stale inputs are rejected.
Durable file-service replacement is a separate host operation. A checksum proves
which bytes were inspected, not authorship, correctness or latest-version status.

Four Acts, twelve Sequences, twenty-four Blocks, ninety-six Mini-Blocks and
25 shot slots per Mini-Block are a planning scaffold. Three seconds per shot and
75 seconds per Mini-Block are targets, not measured media or guaranteed pacing.
Mechanical source allocation is provisional. Dramatic placement, shot design and
source entailment require explicit editorial reasoning. Missing slots stay gaps.

FDX import retains original screenplay-body paragraphs in project extensions and
preserves the original source file in the initial snapshot. It excludes title-page
and external-note content, keeps unknown body paragraph types as notes, and splits
long normalized paragraphs for the canonical 800-character passage limit. Inputs
beyond the 2,500-passage canonical capacity are rejected rather than silently lost.
Layout, revision colours, omitted title pages and full Final Draft metadata are not
round-tripped. FDX XML entities/DTDs are rejected. The legacy binary .fdr format is
not supported by this importer.

A source passage normally belongs to a Mini-Block. The authoring ledger stores
explicit shot mappings separately; the unchanged canonical observer still reports
its own shotSpecificMappingVerified=false. Do not override that fact when reporting
its output. Prompt citations and schema checks do not independently prove semantic
truth or image continuity.

Image registration requires Pillow in the available Python host. It decodes and
converts supplied bytes to lossless WebP and records a hash and portable path.
Registered images are candidates: no Save marker, acceptance or Lock is fabricated.
The live application and its /api/local-ai/assets/ routes are not updated or hosted.
The next snapshot reports unavailable assets; don't imply absent bytes were restored.

The package has not been tested on Go or every ChatGPT surface. Local CLI tests
and fresh-process recovery do not prove fresh-conversation host recovery or image
generation orchestration. Those require separate acceptance in the intended host.
No public listing approval, cross-plan availability or subscription entitlement is
established by this private release.

Version 0.3 adds explicit project-model assessments, truth categories, declared
contradictions, proposal adoption/rejection, runtime computation and learning feedback.
Known records are source observations with evidence, not independently proved world
facts. Inference and artistic judgment remain labelled. Synthetic additions are allowed;
the original source and synthetic origin remain distinguishable after adoption.
A decision record reports the supplied authority; it does not authenticate that human.

Canonical 2,400-slot capacity and baseline timing are separate from the physical
production plan. Explicit slot sharing can represent compression, but does not prove
coverage or a perfect story. Decimal duration/frame calculations are checked; actual
render timing, semantic contradictions not declared in the ledger, and artistic quality
are not automatically verified. No new scoring formula is introduced. Time, money and
resources remain execution constraints; this release does not estimate or eliminate them.
